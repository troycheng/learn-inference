# Learn Inference

这是一份面向推理工程师和工程架构人员的推理系统学习笔记。

目标不是罗列框架参数和优化术语，而是建立一套能够解释现象、估算成本、判断优化方向的基础模型。希望读者学完以后，遇到新的模型、硬件或推理框架时，仍然能回答：

- 模型必须完成哪些计算，哪些步骤存在依赖？
- 一次推理需要多少计算、内存和数据搬运？
- 当前性能受计算、带宽、容量、通信还是调度限制？
- 某项优化减少了什么，又增加了什么代价？
- 它改善的是延迟、吞吐还是 SLO 内的有效吞吐？

## 适合谁

- 维护 GPU 推理服务或推理集群的工程师；
- 熟悉部署、监控和压测，但理论基础不够系统的工程师；
- 需要评估量化、Kernel 优化、调度或多卡方案的架构人员；
- 希望从工程现象反推模型和硬件行为的初学者。

默认读者了解基本编程和服务端概念，不要求具备训练、反向传播或 CUDA 编程背景。

## 写作原则

- 先讲可迁移的原理，再讲具体框架或实现；
- 明确区分计算量 `FLOPs` 和计算速率 `FLOP/s`；
- 给公式时同时给出变量、单位和适用假设；
- 区分理论下界、近似分析和实际测量；
- 不用单一指标替代瓶颈分析；
- 优化结论必须说明适用 workload 和代价。
