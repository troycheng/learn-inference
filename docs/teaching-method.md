# 课程讲解规范

这份规范解决一个具体问题：读者数学基础一般，但需要真正理解模型，而不是只记住术语。

课程先用第 0 课统一最小数学语言，包括 shape、轴、归约、广播、点积、矩阵乘法、Linear 和 Embedding。后续课程在第一次使用更具体的数学动作时，再结合模型问题继续解释，不假设读者已经完成系统的线性代数课程。

## 一条硬规则

**先解释为什么需要这个东西，再解释它怎样计算。**

例如，讲卷积时只说“局部窗口对应相乘再求和”只是描述计算步骤，没有说明它为什么存在。语言模型课程中的每个概念都必须先回答：它解决了哪一个信息处理问题？去掉它会缺少什么能力？

## 每个概念固定走六步

### 1. 提出一个具体问题

不要从定义或公式开始。

```text
Attention：代词“它”怎样找到前文所指的对象？
RMSNorm：向量数值忽大忽小时，怎样把尺度拉回稳定范围？
Residual：经过一次变换后，怎样保留原来的信息？
MoE Router：有很多套 FFN 时，当前 token 应该使用哪几套？
```

### 2. 先画数据流图

图中只放本节需要的对象。箭头表示“谁的输出交给谁”，每个框使用动词说明动作。

```mermaid
flowchart LR
    A["输入分数"] --> B["取指数并归一化"]
    B --> C["总和为 1 的概率"]
```

流程与依赖可以使用 Mermaid；矩阵、轴、函数曲线和容易混淆的局部计算优先使用直接标注数字与 shape 的 SVG 插图。选择哪种形式只看它是否让关系更容易理解。

### 3. 用生活语言解释作用

生活类比只负责建立第一印象，随后必须回到模型对象。例如 Router 可以类比派单，但要立即说明：订单是 token 向量，接单者是不同参数的 FFN，派单分数由一个可学习的 Linear 产生。

### 4. 用小数字走一遍

第一次计算最多使用：

- 2～3 个 token；
- 2～4 维向量；
- 2～4 个候选项；
- 能手算的整数或一位小数。

先展示每一步的输入和输出，再总结规律。不得一上来使用 `4096 × 12288` 这样的真实规模。

### 5. 最后给 shape 和公式

公式前必须有符号表和一句中文读法。

| 符号 | 含义 | 单位或 shape |
| --- | --- | --- |
| `T` | 本轮同时处理的 token 数 | 个 |
| `H` | 每个 token 向量的宽度 | 维 |
| `X` | 输入 hidden states | `[T, H]` |

公式后必须代回刚才的小例子，证明它不是一条孤立的记忆材料。

### 6. 回到 Qwen3.5 和工程问题

每节最后回答：

- 它在 Qwen3.5 哪个位置？
- 官方配置中的哪个字段控制它？
- Prefill 和 Decode 时输入 shape 有什么不同？
- 它会产生权重、中间值、KV Cache 还是 recurrent state？
- 哪些优化方法会改变它？

## 数学采用三级递进

| 层级 | 表达方式 | 目的 |
| --- | --- | --- |
| A：直观 | 图、箭头、自然语言 | 先知道对象和作用 |
| B：可手算 | 小向量、小矩阵、逐步表格 | 看见计算怎样发生 |
| C：可迁移 | shape、通用公式、数量级 | 用于阅读配置和工程判断 |

任何读者如果在 B 层还不能复述，就不进入 C 层。课程不以公式数量体现深度。

## 算子的讲解方式

算子不单独罗列百科定义。它第一次出现在模型链路中时，使用同一张卡片解释：

| 项目 | 必须回答的问题 |
| --- | --- |
| 作用 | 为什么需要这个算子？ |
| 输入 | 输入中的每一维表示什么？ |
| 动作 | 它具体对哪些数做什么？ |
| 输出 | 输出中的每一维表示什么？ |
| 不变量 | 哪些 shape 或语义没有改变？ |
| 相邻关系 | 上一个算子为什么把结果交给它？ |
| 工程影响 | 它产生权重、临时结果还是长期状态？ |

核心算子按出现顺序讲解：

```text
Gather / Embedding
→ Linear
→ Softmax / Top-K / Sampling
→ Add / Mul / SiLU
→ Reduction / Rsqrt / RMSNorm
→ Reshape / Transpose / MatMul / Mask
→ Concat / Slice / Cache 读写
→ Causal Conv / Gate / State Update
→ Router / Gather / Scatter / Weighted Sum
```

## 图表使用原则

- 数据流和依赖关系使用流程图；
- Prefill/Decode 使用时序图；
- Dense/MoE、MHA/GQA 使用对比表；
- shape 变化使用逐步表格；
- 图和问题的数量由理解需要决定，不设固定上限；
- 同一个概念可以依次使用全局定位图、局部数据流图、小数字计算表、shape 表、时序图和对比图；
- 问题应形成连续的理解链，例如“它解决什么问题 → 为什么这样设计 → 怎样计算 → 前后连接什么 → 工程上改变什么”；
- 当一张图要求读者同时记住太多关系时，把它拆成递进的多张图；拆分服务于理解，不追求图少；
- 多张图复用相同名称、方向和视觉符号，避免读者每次重新学习图例；
- 颜色不是理解图的必要条件，保证黑白显示仍能读懂。

图表只是解释工具。不能为了满足版式规则删掉必要步骤，也不能用更多图表掩盖没有讲清楚的因果关系。最终判断只有一个：读者能否沿着图和问题，自己复述完整过程。

## 每课固定结构

```text
这课解决什么真实问题
→ 必要的全局定位图
→ 前置概念检查
→ 概念 1：六步讲解
→ 概念 2：六步讲解
→ 把两者接回完整链路
→ Qwen3.5 配置映射
→ 三个常见误解
→ 口头复述题
→ 小数字练习
→ 工程判断题
→ 原始资料
```

问题与答案直接合并进正文的正确位置。笔误直接改正，不把纠错过程当作知识点。

## 深入浅出的验收标准

一节课合格，需要同时满足：

1. 不看公式也能说清概念解决什么问题；
2. 能用小数字手动走完关键计算；
3. 能写出输入输出 shape；
4. 能在 Qwen3.5 结构图中找到它；
5. 能解释至少一个相关优化为什么可能有效；
6. 不能靠背诵术语蒙混过关。

如果读者只能复述定义，不能回答“为什么存在、怎样计算、前后接了什么、改变输入后结果怎样变化”，说明课程还没有讲清楚。此时应继续补充问题、例子或图表，或者重写解释，而不是急着进入下一个概念。
