# 补充专题：数值精度与量化基础

第 8 课按 dtype 计算权重字节数，第 9 课讨论量化的性能收益。两者之间还有一个计算问题：原来用浮点数保存的权重，改成 4 位整数后，矩阵乘法实际用了哪些数？

下面用同一个 Linear 比较原始权重和量化权重。读完后应能根据 Scale 算出近似值，并解释误差怎样影响输出。

## 1. 低精度表示与缩放系数

低精度格式能表示的数更少。浮点格式的可表示数通常不是等间距的；整数编码则可以通过缩放系数（Scale）对应到一组等间距的实数。

本例采用对称 INT4 量化，整数编码使用 `-7` 至 `7`。当 `scale=0.5` 时：

| 整数编码 | -7 | -6 | … | -1 | 0 | 1 | … | 6 | 7 |
| --- | ---: | ---: | --- | ---: | ---: | ---: | --- | ---: | ---: |
| 对应的近似实数 | -3.5 | -3.0 | … | -0.5 | 0 | 0.5 | … | 3.0 | 3.5 |

相邻两个近似值间隔 0.5，因此 0.6 不能被准确表示，只能用附近的 0.5 代替。Scale 决定整数每增加 1，实际数值增加多少。

有符号 INT4 本身能编码 `-8` 至 `7`。这里空出 `-8`，让正负范围对称，便于手算；这是教学例子的约定，并非所有 INT4 实现都如此。分组大小也会缩到 2 个数，不代表部署格式支持这么小的分组。

## 2. 量化与反量化

设 `w` 是原始权重，`q` 是整数编码，`w_hat` 是反量化后的近似权重，`scale` 为正数。计算顺序为：

$$
q=\mathrm{clip}\left(\mathrm{round}(w/\mathrm{scale}),-7,7\right),\qquad \hat{w}=\mathrm{scale}\times q
$$

`round` 把商舍入到最近的整数；`clip` 把超出范围的整数截到端点。反量化只需乘回 Scale，它不能恢复舍入时丢掉的小数。

对 `w=0.6`、`scale=0.5`：

```text
除以 Scale： 0.6 / 0.5 = 1.2
取最近整数： round(1.2) = 1
检查范围：   1 在 -7 至 7 内，保持不变
反量化：     1 × 0.5 = 0.5
数值误差：   0.5 - 0.6 = -0.1
```

如果仍用这个 Scale 处理 4.2，商是 8.4，舍入为 8 后超出上限，只能截成 7，最后得到 3.5。此时误差为 -0.7，既包含舍入误差，也包含截断造成的损失。

固定整数范围时，Scale 越小，刻度越细，但可覆盖的实数范围也越窄。Scale 越大，能容纳更大的数，较小的数却更容易落到同一个刻度上。

脚本使用最近偶数舍入：恰好位于两个整数中间时，选择偶数，例如 `3.5→4`、`2.5→2`。全零分组把 Scale 设为 1，编码仍全为 0，避免除以 0。

量化与反量化的格式定义可对照 [TensorRT 文档](https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/quantized-types-schemes.html)，实际部署应使用对应格式的编码范围和分组约束。

## 3. 同一个 Linear 的量化前后结果

只看一个 token 的四维输入 `x`，输出两维。沿用课程的权重存储约定：`W` 的每一行计算一个输出坐标，所以 `W` 的 shape 是 `[2,4]`。

```text
x = [1, 2, -1, 0.5]

W = [[0.2, -0.4,  0.6, 3.5],
     [0.1,  0.3, -0.5, 0.7]]
```

原始输出逐行计算：

```text
y[0] = 0.2×1 + (-0.4)×2 + 0.6×(-1) + 3.5×0.5 = 0.55
y[1] = 0.1×1 +    0.3×2 + (-0.5)×(-1) + 0.7×0.5 = 1.55
```

先让整张矩阵共用一个 Scale。取最大绝对值除以 7：`scale=3.5/7=0.5`。本例用这种简单的定标方法，实际算法还可以根据误差选择不同的范围。

量化和反量化后的权重为：

```text
整数编码 Q = [[0, -1,  1, 7],
              [0,  1, -1, 1]]

近似权重 W_hat = [[0, -0.5,  0.5, 3.5],
                 [0,  0.5, -0.5, 0.5]]
```

输入 `x` 保持不变，用 `W_hat` 计算同一个 Linear：

```text
y_hat[0] = 0×1 + (-0.5)×2 + 0.5×(-1) + 3.5×0.5 = 0.25
y_hat[1] = 0×1 +    0.5×2 + (-0.5)×(-1) + 0.5×0.5 = 1.75
```

| 结果 | 输出第 0 维 | 输出第 1 维 |
| --- | ---: | ---: |
| 原始 Linear | 0.55 | 1.55 |
| 反量化后的 Linear | 0.25 | 1.75 |
| 输出误差 | -0.30 | +0.20 |

每个输出误差仍是一项点积。以第 0 维为例，权重误差为 `[-0.2,-0.1,-0.1,0]`，与输入 `[1,2,-1,0.5]` 点积后得到 -0.3。换一组输入，输出误差也会变，不能仅凭权重误差推断所有请求的质量损失。

脚本在普通浮点数中复算这个过程，用来隔离权重量化误差。真实 Kernel 的低精度乘法、累加和输出转换还可能产生额外误差。

## 4. 分组量化与异常值

矩阵里的 3.5 决定了全局 Scale，其他数大多只有零点几。用同一把刻度表示它们时，0.1、0.2 都变成了 0。相对周围数值特别大的数，通常称为异常值（Outlier）；这里讨论的是数值分布，不表示它一定是错误数据。

把每行相邻的两个数分为一组，每组分别取“最大绝对值除以 7”，结果如下。表中小数是近似值。

| 原始分组 | Scale | 整数编码 | 反量化结果 |
| --- | ---: | --- | --- |
| `[0.2,-0.4]` | 0.057143 | `[4,-7]` | `[0.228571,-0.4]` |
| `[0.6,3.5]` | 0.5 | `[1,7]` | `[0.5,3.5]` |
| `[0.1,0.3]` | 0.042857 | `[2,7]` | `[0.085714,0.3]` |
| `[-0.5,0.7]` | 0.1 | `[-5,7]` | `[-0.5,0.7]` |

3.5 现在只影响自己所在的那组，不再决定其他组的刻度。将这四组近似值放回原矩阵，再乘同一个 `x`：

| 量化方式 | Linear 输出 | 相对原始输出的误差 |
| --- | --- | --- |
| 整张矩阵共用 Scale | `[0.25,1.75]` | `[-0.30,+0.20]` |
| 每行每 2 个数共用 Scale | 约 `[0.678571,1.535714]` | 约 `[+0.128571,-0.014286]` |

在这个输入上，分组后两项输出误差都更小。但误差可能在点积中抵消，也可能叠加，不能据此推断任意输入或最终任务质量都单调改善。

分组更细还需要保存更多 Scale。本例有 8 个权重，理想 INT4 编码占 4 Byte。假设每个 Scale 用 FP16 保存，一个 Scale 再占 2 Byte；四个 Scale 共占 8 Byte。加上 Scale 后，两种方案分别至少需要 6 Byte 和 12 Byte，尚未计入对齐和格式开销。

这也是实际格式不会只追求最小分组的原因。分组大小同时影响误差、元数据容量和 Kernel 的处理方式。

## 5. W4A16 与 FP8 的含义

W4A16 中，W 表示权重，A 表示激活；4 和 16 是对应位宽。这个缩写本身没有交代 Scale 的粒度、16 位激活使用 FP16 还是 BF16，也没有交代累加精度。部署时仍需核对第 8 课区分的保存、计算、累加和输出 dtype。

本例只是 W4A16 所涉及的“低比特权重近似”演示，没有真正执行 16 位激活计算，也没有把整数打包成 4 位数据。Weight-only Kernel 可以在片上按需要反量化，不必先在显存里恢复一整张浮点权重矩阵。

FP8 使用浮点编码，其可表示数不是本例 INT4 的等间距刻度。许多 FP8 方案也使用 Scale，但转换动作是舍入到可表示的 FP8 数值，而不是舍入到整数。不能直接把本例公式中的编码范围换成 8 位整数，就当作 FP8 的计算。[TensorRT FP8 定义](https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/quantized-types-schemes.html)

## 6. 数值误差与生成结果

模型优化后的验证至少涉及三个不同问题：

| 比较内容 | 能回答什么 |
| --- | --- |
| 中间张量、Logits 的绝对或相对误差 | 实现有没有明显错误，数值偏差出现在哪一层 |
| 固定输入下的候选排序、输出序列 | 偏差是否改变了本次生成选择 |
| 代表性任务的质量指标 | 变化是否影响实际使用 |

两次生成文字相同，不代表 Logits 相同；文字不同，也不能单凭这一项判断实现出错。例如候选分数 `[1.000,0.999]` 变成 `[0.998,1.001]`，贪心选择就会改变。自回归生成随后使用了不同的输入，后续文本差异可能继续扩大。

缓存复用、矩阵切分等操作在数学上应保留原计算，适合做数值等价性检查。量化则主动改变了数值表示，除了误差检查，还需要任务质量评估。两者不能使用同一条“必须完全相同”的验收规则。

即使没有量化，浮点加法顺序、批量形状或 Kernel 也可能带来小幅数值差异。验收应明确参考实现、dtype 和容差，不把“同一模型”理解成任何环境都能逐位复现。[PyTorch 数值精度说明](https://docs.pytorch.org/docs/2.15/notes/numerical_accuracy.html)
