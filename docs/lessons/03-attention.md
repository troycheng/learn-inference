# 第 3 课：Attention 的计算原理

上一课把 Token Mixer 暂时当成黑盒。现在有一个具体问题：FFN 只处理各自位置的特征，“杯子”位置的信息怎样进入后面“它”的表示？

Full Attention 的做法是：让“它”与所有允许读取的位置分别计算匹配分数，再按分数汇总这些位置携带的信息。它得到的是一条新的向量，不是某个 token，也不是一个词表概率。

Qwen3.5 的另一种 Token Mixer 是 Gated DeltaNet，它把历史持续写入固定大小的状态。第 5 课会讲这条路径。本课只分析 Full Attention。

```text
Full Attention：直接读取所有可见位置
Gated DeltaNet：通过固定大小的状态读取历史
```

`Full` 指读取范围。序列中有 `T` 个位置时，一个 Attention 头在概念上会计算一张 `T×T` 的分数表。Decoder 受因果约束，只能读取当前位置和它左边的内容。

后面的图和手算都使用同一个例子：

```text
小明把杯子放在桌上，然后拿起它。

位置 1   位置 2   位置 3
小明     杯子     它
```

这里省略了句子中的其他位置，也没有照搬真实 Tokenizer 的切分。三个标签只为说明计算，Q、K、V 和遮罩矩阵始终沿用这组编号。

## 1. Attention 是一次加权读取

进入 Attention 前，三个位置各有一条隐藏状态 `x1`、`x2`、`x3`。它们是当前 Decoder Layer 收到的向量，不一定是最初的 Embedding。

先只看位置 3。Attention 用 `x3` 生成查询向量 `Q3`，把它与三个位置的键向量 `K1`、`K2`、`K3` 比较，得到三项权重。随后，三个位置的值向量 `V1`、`V2`、`V3` 按这些权重相加：

```text
Q3 与 K1、K2、K3 比较
→ 得到三个权重
→ 用三个权重汇总 V1、V2、V3
→ 得到位置 3 的 Attention 输出
```

![位置 3 怎样读取三个可见位置](../assets/03-qkv-intuition.svg?rev=20260810-1)

这是一种“软读取”。它不会从三个位置中硬选一个；每个可见位置都能贡献信息，只是权重不同。

## 2. Q、K、V：匹配依据与返回内容

Q、K、V 可以借用检索系统来理解。查询请求会生成检索条件，候选记录用索引特征接受比较，命中后返回记录内容。Attention 的三组向量承担相近的分工：

| 符号 | 名称 | 作用 | 检索类比 |
| --- | --- | --- | --- |
| `Q` | 查询向量（Query） | 当前处理的位置拿什么特征去匹配 | 查询条件 |
| `K` | 键向量（Key） | 每个候选位置拿什么特征接受比较 | 索引特征 |
| `V` | 值向量（Value） | 候选位置最终向输出提供什么信息 | 返回内容 |

这个类比只解释计算分工。K 不是唯一主键，Attention 也不是精确查表。Q/K 的点积产生连续分数，所有可见位置的 V 通常都会参与结果。

K 和 V 分开很有必要。用什么特征判断两个位置相关，与相关位置应该传出什么信息，并不是一回事。模型可以用词性、位置和上下文关系做匹配，同时从命中的位置传出对象、属性或动作等特征。

这些用途没有写死在某个向量坐标中。训练会调整投影权重，使某些头逐渐学会对有用的关系打出更合适的分数。

### 2.1 隐藏状态怎样变成 Q、K、V

设 RMSNorm 后的隐藏状态为 `X:[B,T,H]`。三组 Linear 分别计算：

$$
Q=XW_Q^T,\qquad K=XW_K^T,\qquad V=XW_V^T
$$

`W_Q`、`W_K`、`W_V` 是模型参数。Q、K、V 是当前请求在这一层产生的中间数据。同一个位置的隐藏状态经过三组不同权重重新组合，所以会得到三种不同表示。

Q、K、V 都来自同一组 `X`，因此叫自注意力（Self-Attention）。交叉注意力会让 Q 和 K/V 来自不同输入，本课不展开。

## 3. 完整算一遍位置 3

只看一个头，并把向量宽度缩小到 `D=2`。每个位置其实都有自己的 Q、K、V；表中只列 `Q3`，因为这一遍只计算位置 3 的输出。

| 位置 | token | 本次使用的 Q | K | V |
| ---: | --- | --- | --- | --- |
| 1 | 小明 |  | `[1,0]` | `[2,0]` |
| 2 | 杯子 |  | `[1,1]` | `[0,2]` |
| 3 | 它 | `[1,1]` | `[0,1]` | `[1,1]` |

这些数字是为手算设计的。它们不是词语的固定编码，也不表示某一维永远具有某种语义。

### 3.1 Q/K 点积得到匹配分数

`Q3` 分别与三条 K 做点积：

$$
\begin{aligned}
Q_3\cdot K_1&=[1,1]\cdot[1,0]=1\\
Q_3\cdot K_2&=[1,1]\cdot[1,1]=2\\
Q_3\cdot K_3&=[1,1]\cdot[0,1]=1
\end{aligned}
$$

第二项最高，因此这组数字中“杯子”与“它”匹配得最强。图中的三次比较正是这三行点积：

![Q3 分别与三条 K 计算分数](../assets/03-one-query-scores.svg?rev=20260810-1)

点积会把 `D` 项乘积加起来。头维度越大，分数的绝对值通常也越容易变大。Attention 把分数除以 `√D`，避免 Softmax 过早集中到极少数位置：

$$
\frac{[1,2,1]}{\sqrt{2}}\approx[0.707,1.414,0.707]
$$

Qwen3.5-9B 的 Full Attention 头维度是 `D=256`，实际缩放系数为 `1/√256=1/16`。缩放改变分数之间的距离，不改变它们的大小顺序。

### 3.2 Softmax 把分数变成权重

位置 3 位于最后，前面没有需要遮住的未来位置。三个缩放分数经过 Softmax 后得到：

![一行分数经过 Softmax 变成权重](../assets/03-score-to-weight.svg?rev=20260810-1)

未截断的权重是：

```text
位置 1“小明”：0.248255...
位置 2“杯子”：0.503490...
位置 3“它”：  0.248255...
```

Softmax 保留分数的大小关系，把每项变成非负权重，并让整行权重之和等于 1。图中显示到三位小数，所以 `0.248+0.503+0.248=0.999`；完整精度的和仍然是 1。

Attention Score 和 Attention Weight 是两种数据：

```text
Score： Q/K 点积并缩放后的分数
Weight：分数经过遮罩和 Softmax 后的权重
```

### 3.3 权重乘 V，再逐项相加

Q/K 的工作到权重为止。真正进入输出的是 V：

![三个权重怎样汇总三条 V](../assets/03-weighted-values.svg?rev=20260810-1)

用完整精度计算：

$$
0.248255[2,0]+0.503490[0,2]+0.248255[1,1]
\approx[0.745,1.255]
$$

这条 `[2]` 向量是位置 3 在这个头中取回的信息。它不是“杯子”的 Token ID，也不是下一个 token 的概率。完整模型还要拼接多个头，经过输出投影、残差连接、FFN 和后续 Decoder Layer。

位置 3 的单头计算可以概括为：

```text
Q/K 负责算权重
权重负责汇总 V
输出仍是一条隐藏特征向量
```

## 4. 从一个位置推广到整段序列

前面只用了 `Q3`。把位置 1 和位置 2 的查询也加入，得到三张矩阵：

$$
Q=
\begin{bmatrix}
1&0\\
0&1\\
1&1
\end{bmatrix},\quad
K=
\begin{bmatrix}
1&0\\
1&1\\
0&1
\end{bmatrix},\quad
V=
\begin{bmatrix}
2&0\\
0&2\\
1&1
\end{bmatrix}
$$

Q 的第 `i` 行与 K 的第 `j` 行点积，得到分数矩阵的第 `i` 行第 `j` 列。因此：

$$
\frac{QK^T}{\sqrt{2}}=
\begin{bmatrix}
0.707&0.707&0\\
0&0.707&0.707\\
0.707&1.414&0.707
\end{bmatrix}
$$

行和列的含义不能弄反：

```text
第 i 行：位置 i 正在读取其他位置
第 j 列：位置 j 正在被读取
```

第 3 行就是上一节手算的 `Q3` 与 `K1`、`K2`、`K3`。矩阵乘法没有改变算法，只是把多个查询位置放到一次计算中。

### 4.1 因果遮罩挡住未来位置

Decoder 生成 token 时只能使用已经出现的内容。位置 2 可以读取位置 1 和自己，不能读取位置 3。图中的每一行都是一个查询位置，每一列都是它准备读取的位置：

训练时，位置 2 的最终表示用于预测位置 3 的 token。允许它读取第 3 列，相当于把待预测内容提前放进了输入，真实生成时却没有这项信息。

![因果遮罩规定每一行可以读取哪些列](../assets/03-causal-mask.svg)

因果遮罩（Causal Mask）记作 `M`：

$$
M=
\begin{bmatrix}
0 & -\infty & -\infty\\
0 & 0 & -\infty\\
0 & 0 & 0
\end{bmatrix}
$$

它不是 Q、K、V，也不是从 Q/K 计算出的分数。它在 Softmax 前与分数矩阵逐元素相加：

$$
S_{masked}=\frac{QK^T}{\sqrt{D}}+M
$$

未来位置被改成负无穷，经过 Softmax 后权重为 0。这个例子的遮罩后分数为：

$$
S_{masked}=
\begin{bmatrix}
0.707&-\infty&-\infty\\
0&0.707&-\infty\\
0.707&1.414&0.707
\end{bmatrix}
$$

每一行单独做 Softmax：

$$
A\approx
\begin{bmatrix}
1&0&0\\
0.330&0.670&0\\
0.248&0.503&0.248
\end{bmatrix}
$$

最后计算 `O=AV`：

$$
O\approx
\begin{bmatrix}
2.000&0\\
0.660&1.340\\
0.745&1.255
\end{bmatrix}
$$

这里的 `A` 为便于阅读只显示三位小数，`O` 使用未截断权重计算。

第 3 行与前面的单位置计算相同。现在可以把整个单头 Attention 写成两条公式：

$$
A=\mathrm{softmax}\left(\frac{QK^T}{\sqrt{D}}+M\right),\qquad O=AV
$$

![缩放点积 Attention 的主计算](../assets/03-attention-flow.svg?rev=20260810-1)

| 公式部分 | 实际计算 |
| --- | --- |
| `QK^T` | 每条 Q 与每条 K 点积，得到分数矩阵 |
| 除以 `√D` | 控制分数尺度 |
| `+M` | 把未来位置的分数改成负无穷 |
| `Softmax` | 每一行分数变成权重 |
| `AV` | 按权重汇总每个位置的 V |

因果遮罩限制“每一行能读哪些列”，不要求 Prompt 中的多个已知位置依次执行。Prefill 时，多个已知位置的 Q/K/V 可以放进较大的张量中计算，只是它们使用不同的遮罩行。第 4 课会继续区分 Prefill 与逐 token Decode。

仓库中的 [Attention 手算程序](../../examples/attention_walkthrough.py) 使用同一组 Q、K、V。它不依赖第三方库，可以逐行核对缩放分数、遮罩、Softmax 权重和最终输出。

RoPE、多头和 GQA 都不改变“Q/K 算权重，再用权重汇总 V”这条主线。它们分别补充位置信息、增加多组匹配空间、减少 K/V 头数。

## 5. RoPE：把相对位置写进 Q/K 点积

只比较内容还不够。下面两句话用了完全相同的词，交换位置以后，谁批评谁也跟着变了：

```text
小明批评小李
小李批评小明
```

距离也会影响关系。同一个词出现在当前位置前 2 个 token 或前 2000 个 token，位置关系显然不同。Attention 需要分辨两个 token 谁在前、谁在后，以及相隔多少位置。

RoPE 的目标正是让 Q/K 的匹配分数带上这种相对位置。它使用旋转，但旋转只是手段。

### 5.1 用二维箭头理解旋转

暂时从 Q 中取两个数，把它们看成平面上的一根箭头。假设 token 每向后移动一个位置，箭头就多转一个固定角度 `θ`：

```text
位置 0：转 0θ
位置 1：转 1θ
位置 2：转 2θ
...
位置 m：转 mθ
```

K 中对应的两个数也按自己的位置旋转。如果当前 token 的 Q 位于较后的位置 4，前文 token 的 K 位于较前的位置 2，它们分别转过 `4θ` 和 `2θ`，两根箭头之间相差 `2θ`。

把两个 token 一起移到 Q 的位置 14 和 K 的位置 12，各自都额外转了 `10θ`，但夹角仍是 `2θ`。绝对角度变了，相对角度没有变。

![RoPE 让点积感知相对位置](../assets/03-rope.svg?rev=20260809-1)

点积本来就和两根箭头之间的夹角有关。RoPE 利用这一点，让点积中的位置影响只取决于两个 token 相差多少位置。

取一个可以手算的特例：令原始 `q=k=[1,0]`，每前进一个位置旋转 30 度。两个 token 位于位置 2 和位置 4 时，两根箭头分别转到 60 度和 120 度，夹角为 60 度，点积是 `cos(60°)=0.5`。把它们同时移到位置 12 和位置 14，夹角和点积都不变。

这个特例只说明共同移动不会改变相对位置。真实 Q、K 的内容不同，维度也更高，Attention 分数不是一张只按距离查询的固定表。

### 5.2 相对位置怎样进入点积

把位置 `m` 对应的旋转写成 `R_m`，位置 `n` 对应的旋转写成 `R_n`。这一小节暂时把 `q`、`k` 写成列向量，便于表示旋转矩阵；前文 Linear 使用的行向量记法不变。旋转后的 Q、K 点积为：

$$
(R_m q)^T(R_n k)=q^T R_m^T R_n k=q^T R_{n-m}k
$$

公式最后只剩下 `n-m`。原来的两个绝对位置 `m` 和 `n`，在点积中合成了两者的相对位置。

这条公式不能读成“Attention 分数只由距离决定”。`q` 和 `k` 仍然来自两个 token 的内容；只是位置对分数的影响通过 `n-m` 进入。内容和相对位置会一起影响最终匹配分数。

### 5.3 多种旋转速度

真实的 Q/K 不止二维。RoPE 会把参与旋转的维度分成许多二维特征组，每组采用不同的旋转速度。可以把它们想成一排快慢不同的钟表：

- 转得快的表，位置稍有变化，角度就明显不同；
- 转得慢的表，经过较长距离后仍会缓慢变化；
- 单独一只表会周期性转回相同角度，多种速度一起使用，可以形成更丰富的位置差特征。

![RoPE 使用多种旋转速度](../assets/03-rope-frequencies.svg)

这不表示某一组维度被人工指定为“只管近距离”，另一组“只管远距离”。模型会结合所有特征学习怎样使用这些位置信号。RoPE 也不保证越近的 token 权重越高；最终权重仍由 Q/K 内容、相对位置和训练共同决定。

### 5.4 RoPE 只作用于 Q 和 K

RoPE 要改变的是位置之间的匹配分数，而分数来自 Q 与 K 的点积，所以旋转放在 Q/K 上。V 负责携带匹配成功后要汇总的信息，不参与这次匹配，因此不需要做同样的旋转。

旋转不会增加 token 数，也不会改变 Q/K 的 shape，只会改变其中的数值。

### 5.5 Qwen3.5-9B 只旋转部分维度

Qwen3.5-9B 的每个 Full Attention 头有 `256` 维。配置项 `text_config.rope_parameters.partial_rotary_factor=0.25` 表示只有前 `64` 维参与 RoPE，后 `192` 维原样通过：

```text
Q：前 64 维旋转，后 192 维不旋转
K：前 64 维旋转，后 192 维不旋转
V：256 维都不旋转
```

K 经过 RoPE 后才写入 KV Cache，所以缓存复用必须保持位置编号和 RoPE 规则一致。Qwen3.5 正式实现使用 MRoPE；纯文本时可以先按上面的一维位置理解，图片和视频的时间、高度、宽度位置放到第 7 课。

## 6. 多头注意力与 GQA

### 6.1 从前面的单头例子接到多头

前面只跟踪位置编号，所以写成 `Q3`、`K1`、`K2`、`K3`。加入多头以后，要同时区分“第几个头”和“第几个 token 位置”:

| 下标 | 含义 | 例子 |
| --- | --- | --- |
| `i、j` | token 位置 | `j=2` 表示“杯子”所在的位置 |
| `h` | 查询头编号 | `h=1` 表示第 1 个查询头 |
| `g` | K/V 头编号 | `g=1` 表示第 1 个 K/V 头 |

用完整下标重写前面的手算：位置 3 在第 1 个查询头中的 Q 是 `Q(h=1,i=3)`；它依次与 `K(g=1,j=1)`、`K(g=1,j=2)`、`K(g=1,j=3)` 比较。最后得到第 1 个头在位置 3 的输出：

$$
O(h=1,i=3)=[0.745,1.255]
$$

多头注意力（Multi-Head Attention，MHA）会让同一组隐藏状态再进入第 2 个、第 3 个乃至更多查询头。每个头使用自己的投影权重，重复相同的计算：

```text
本头的 Q/K 点积
→ 缩放、因果遮罩和 Softmax
→ 用本头的权重汇总 V
→ 得到本头在各 token 位置的输出
```

![从前面的单头手算扩展到多个头](../assets/03-multihead-bridge.svg?rev=20260811-1)

各头读取的是同一段 token 序列，区别在于投影权重。第 1 个头可能给“杯子”较高权重，第 2 个头可以形成另一组权重。模型没有为每个头预先规定固定职责，这些匹配方式由训练形成。

对完整序列，每个查询头输出 `[B,T,D]`。`Nq` 个头堆在一起是 `[B,Nq,T,D]`，调整轴顺序并沿特征维拼接后得到 `[B,T,Nq×D]`。Qwen3.5-9B 中：

$$
Nq\times D=16\times256=4096=H
$$

这里讲的是 MHA。MLA 通常指 Multi-head Latent Attention，它会把 K/V 表示压缩到潜在空间，结构和缓存方式都不同。Qwen3.5-9B 的 Full Attention 使用 GQA，本课不把 MLA 混入这条数据流。

### 6.2 GQA 让多个查询头共用 K/V

普通 MHA 中，查询头和 K/V 头一一对应。如果有 4 个查询头，也有 4 组 K/V 头。分组查询注意力（Grouped-Query Attention，GQA）保留 4 个查询头，但让它们共用较少的 K/V 头。

“共用一个 K/V 头”并不是只共用某个 token 的 K 和 V。一个 K/V 头仍然包含序列中所有位置：

```text
K/V 头 g=1：K(g=1,j=1...T)，V(g=1,j=1...T)
```

假设查询头 `h=1` 到 `h=4` 共用 K/V 头 `g=1`。在位置 `i=3`：

```text
Q(h=1,i=3) 与 K(g=1,j=1...T) 比较，得到第 1 组权重
Q(h=2,i=3) 与 K(g=1,j=1...T) 比较，得到第 2 组权重
Q(h=3,i=3) 与 K(g=1,j=1...T) 比较，得到第 3 组权重
Q(h=4,i=3) 与 K(g=1,j=1...T) 比较，得到第 4 组权重
```

四个查询头虽然读取同一组 K/V，但 Q 不同，所以 Attention 权重和输出仍然可以不同。

仍用前面的三位置手算。保留同一组 K 和 V，只换位置 3 的 Q：

```text
查询头 h1：Q=[1,1] → 权重约 [0.248,0.503,0.248] → 输出 [0.745,1.255]
查询头 h2：Q=[0,1] → 权重约 [0.198,0.401,0.401] → 输出 [0.797,1.203]
```

两条查询头没有各存一份 K/V。它们读取同一组 `K1...K3` 和 `V1...V3`，但各自的 Q 不同，点积、Softmax 权重和最终输出也随之不同。这就是 GQA 中“共享 K/V，但不共享查询结果”的含义。

![MHA 与 GQA 的 K/V 共享方式](../assets/03-gqa.svg?rev=20260811-1)

Qwen3.5-9B 的配置是：

```text
Nq  = 16 个查询头
Nkv =  4 个 K/V 头
D   = 256
```

每 4 个查询头共用一个 K/V 头。总投影宽度为：

```text
Q：16 × 256 = 4096
K： 4 × 256 = 1024
V： 4 × 256 = 1024
```

与 16 个查询头各自保留 K/V 的普通 MHA 相比，K/V 投影宽度和 KV Cache 元素数降为 1/4。Q、输出投影、FFN 和其他层没有随之缩小，因此整模型显存和总计算量不会同时降为 1/4。

优化实现可以让多个查询头直接读取共享 K/V；朴素实现也可能先在逻辑上把 K/V 展开到 16 头。两种实现的 Attention 结果相同，内存访问和临时数据量不同。

## 7. Qwen3.5-9B 的完整 Attention 子层

### 7.1 从各头计算到子层输出

下面这张图把前面分开讲过的计算全部接起来，包括 Qwen3.5-9B 特有的 Q/K 归一化、部分 RoPE 和 Attention 输出门控：

![Qwen3.5-9B 多头 Attention 的完整流程](../assets/03-qwen-attention-full-flow.svg?rev=20260811-1)

图中的 Attention 区域会执行 16 次查询头计算。第 `h` 个查询头先找到它对应的 K/V 头 `g`，再完成：

$$
A_h=\mathrm{softmax}\left(\frac{Q_hK_g^T}{\sqrt D}+M\right),\qquad O_h=A_hV_g
$$

每个 `O_h` 的 shape 是 `[B,T,D]`。16 个结果先组成 `[B,16,T,256]`，再调整为 `[B,T,16,256]`，最后沿两个特征轴拼接：

```text
[B,T,16,256] → [B,T,4096]
```

Concat 只是把 16 条结果首尾排在同一条特征轴上，并没有让各头互相计算。`o_proj` 随后使用 Linear 重新组合这些特征，信息才会跨头混合。

Qwen3.5 在 Concat 与 `o_proj` 之间还有一组输出门控。它用 `Sigmoid(Gate)` 逐元素调节 `[B,T,4096]`，再交给 `o_proj`。`o_proj` 输出和原输入 X 都是 `[B,T,4096]`，两者最后逐元素相加，得到 Attention 子层输出。

这个输出仍是隐藏状态。它还要经过本层 FFN、后续 Decoder Layer、最终 RMSNorm 和 LM Head，才会形成词表 Logits。

### 7.2 各阶段的实际 shape

Qwen3.5-9B 的 Full Attention 输入是：

```text
X: [B,T,4096]
```

Attention 主计算的 shape 如下：

| 阶段 | shape | 说明 |
| --- | --- | --- |
| 查询 Q | `[B,16,T,256]` | 16 个查询头 |
| 键 K | `[B,4,T,256]` | 4 个键头 |
| 值 V | `[B,4,T,256]` | 4 个值头 |
| 分数矩阵 | 逻辑上为 `[B,16,T,T]` | 每个查询位置对可见位置打分 |
| 每头输出 | `[B,16,T,256]` | 权重乘 V 后的结果 |
| 拼接各头 | `[B,T,4096]` | `16×256=4096` |
| `o_proj` 输出 | `[B,T,4096]` | 回到残差分支所需的 H 维 |

“逻辑上为 `[B,16,T,T]`”很重要。FlashAttention 一类实现不会把完整分数矩阵长期写入显存，而是分块计算 Softmax 和加权结果。但从模型含义看，每个查询位置仍然是在与可见的键位置计算分数。

### 7.3 Qwen3.5 增加的三项处理

标准公式说明了共同的计算骨架。Qwen3.5 还在这条骨架上加入三项处理：

1. **Q/K 归一化**：Q 和 K 按每个头的 256 维做 RMSNorm，再进入 RoPE 和点积。
2. **部分 RoPE**：每头 256 维中有 64 维参与位置旋转。
3. **Attention 输出门控**：模型另外生成一组 `[B,T,4096]` 的门控值，经 Sigmoid 后逐元素调节各头拼接结果，再进入 `o_proj`。

Transformers 实现中的 `q_proj` 一次产生 `[B,T,8192]`，然后拆成两半：

```text
前 4096 个数 → 16 个查询头的 Q
后 4096 个数 → Attention 输出门控
```

这组门控和 SwiGLU 中的门控作用位置不同：

```text
SwiGLU 门控：调节 FFN 的中间特征
Attention 输出门控：调节各头汇总后的结果
```

两组门控来自不同参数，作用在不同子层，调试时要分别跟踪。完整顺序已经画在 7.1 节的流程图中，这里不再重复一遍。

## 8. 推理时需要关注的数据与成本

### 8.1 模型参数、临时数据与缓存

| 对象 | 类型 | 生命周期 |
| --- | --- | --- |
| `W_Q`、`W_K`、`W_V`、`W_O` | 模型参数 | 加载模型时进入设备，被不同请求重复使用 |
| Q/K/V | 当前请求产生的数据 | 由这一层输入和投影权重计算得到 |
| Attention 分数和权重 | 当前请求的中间数据 | 用于完成本次加权汇总 |
| 历史 K/V | 当前请求的缓存状态 | Decode 时保留，供后续 token 复用 |

K/V 既是本轮计算的中间结果，又会在自回归生成中成为缓存。缓存怎样建立、为什么能避免重复计算、容量怎样估算，放在第 4 课展开。

### 8.2 序列长度与 Attention 计算量

Prefill 中有 T 个查询位置，每个位置最多与 T 个键位置比较。分数矩阵在概念上是 `T×T`，所以序列长度增加会迅速增加这部分计算。

因果遮罩挡住了上三角，但普通实现仍要处理大量位置组合。不同内核是否能跳过或分块处理这些计算，要看具体实现，不能只看公式直接断言性能。

### 8.3 GQA 与 K/V 宽度

Qwen3.5 用 4 个 K/V 头服务 16 个查询头。判断 KV Cache 容量时，应使用 `Nkv=4`，不能误用 `Nq=16`。

### 8.4 FlashAttention 的作用范围

它通过分块和在线 Softmax 减少中间矩阵的显存读写。Q/K 打分、因果约束、Softmax、加权 V 这些语义没有消失。

### 8.5 RoPE 与 K Cache

位置旋转发生在 K 写入缓存前。处理缓存复用、前缀拼接或位置重映射时，必须保证位置编号和 RoPE 规则一致，不能只复制一段 K/V 就认为语义一定正确。

## 9. Attention 的概念边界

| 容易混淆的对象 | 准确含义 |
| --- | --- |
| Attention 输出 | 每个查询位置的一条隐藏特征向量，不是 token 或词表概率 |
| `W_Q`、`W_K`、`W_V` | 模型参数；Q、K、V 是它们处理当前请求后产生的数据 |
| K 与 V | K 参与匹配，V 才参与最后的加权汇总 |
| Attention Weight | 某一层、某一个头汇总 V 的权重，不等于模型生成某个 token 的概率 |
| 因果遮罩 | 限制每个查询位置可读取的范围，不会迫使已知 Prompt 按位置串行计算 |
| `T×T` 分数矩阵 | 模型语义上的关系矩阵；FlashAttention 可以避免把完整矩阵长期写入显存 |

一个头中的完整数据流可以复述为：隐藏状态经过三组 Linear 得到 Q、K、V；Q/K 经过位置处理后点积并缩放；因果遮罩和 Softmax 把分数变成权重；权重汇总 V；多个头的结果拼接后经过 `o_proj`，最后与残差分支相加。
